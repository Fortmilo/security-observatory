Runs inside Salesforce with a narrow evidence boundary.

Security boundaries

What the application deliberately does not do

No remediation

No token revocation, API blocking, permission removal, endpoint change, certificate rotation or production write-back.

No secrets or raw credentials

No access tokens, refresh tokens, session IDs, client secrets, certificate bodies, private keys, raw headers or raw IP values.

No external evidence service

Scanning and retained evidence remain in the subscriber Salesforce org. The self-callout targets the same org Tooling API.

Self-callout prerequisite

Manual subscriber-owned authentication

Core SOQL-backed evidence works without the Tooling API self-callout. Tooling-backed families require subscriber-specific authentication through an Auth Provider, External Client App, External Credential, Named Credential and principal.

The package must not own or overwrite subscriber OAuth configuration. A separate least-privilege permission extension may be deployed only after the principal exists.

Release boundary

Public source is curated, not mirrored

The private implementation and its working history are not exposed directly. This public repository may contain selected sanitised source, architecture, setup guidance, synthetic screenshots, validation evidence and contribution material.

Package creation, installation proof and public distribution are stated only when evidence exists. The current public position remains sandbox-first.
