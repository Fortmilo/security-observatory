Evidence levels

Depth, not scanner selection

Every manual, scheduled and supported API-triggered scan uses the same Apex-owned scanner plan. The evidence level changes what is retained, displayed, compared and exported.

Top IssuesRetains and displays the highest-value evidence.
BalancedAdds safe drill-down evidence to the top-issue view.
EverythingRetains full-detail evidence and therefore uses the most storage.

Scan operations

Manual and scheduled execution share the same path

One Scan action

Client code does not own a second scanner list. The same complete scanner plan runs regardless of trigger.

Scheduled scans

Admin-managed, disabled by default and restricted to conservative fixed presets. Overlapping scans are prevented.

Last and next run

The Admin surface shows schedule state, next run, last run and last result using sanitised status only.

Retention

Bounded completed-scan history

Administrators can select a completed-scan retention limit from 1 to 10, with edition-aware defaults and a Developer Edition cap for Everything evidence.

Old noisy detail rows are removed before parent scan records. Failed or running scans are not treated as completed clean baselines.

Recovery and registry

Operational recovery without remediation

Stale scan-lock recovery

Admins may close a confirmed orphan Queued or Running scan to a bounded Failed state when no active scan-lifecycle job remains.

No active-job cancellation

Recent, active or ambiguous scan locks remain blocked. The UI does not expose raw scan or AsyncApexJob IDs.

SBS registry controls

Bundled local SBS metadata can be managed through controlled admin upload without internet update checks or automatic remapping.

Permission boundary

Admin-only and still read-only

Configuration and recovery controls are permission gated. They manage Observatory execution and evidence storage only; they do not revoke tokens, remove permissions, block APIs or alter endpoints.
